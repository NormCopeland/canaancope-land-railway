Your site, and how to work it

The site is a small Node engine your son wrote. Everything you publish is a folder of Markdown and media, and the admin panel is a file manager with an editor attached. This guide covers the two addresses, first-time setup, writing posts, the content tag syntax, and keeping the Railway deployment healthy.

01

How the site is put together

There are three kinds of thing: libraries, folders, and blogs (the engine's word for a post). A library is a top-level section with its own page and URL. Inside it, any folder that contains a config.json is a blog; any folder without one is just a folder for grouping. The About Me area is a special library with only content and media.

public/
├── libraries/
│   ├── notes/                       ← library, page at /notes
│   │   ├── index.html               ← created by "New Library"
│   │   ├── folder.json
│   │   ├── 2026-09-12_welcome/      ← blog, URL /notes/2026-09-12_welcome
│   │   │   ├── config.json          ← title, dates, featured, private
│   │   │   ├── content.md           ← the post
│   │   │   └── media/               ← photos, video, audio for this post
│   │   └── 2026-08-30_camping/
│   └── projects/
│       └── woodworking/             ← plain folder (has folder.json)
│           └── bench/               ← blog, URL /projects/woodworking/bench
├── aboutme/
│   ├── content.md
│   └── media/
└── media/logo.png                   ← site logo; favicon is built from it

On Railway all of this lives on the persistent volume at /data/public, so it survives redeploys. The folder name of a blog is its URL slug, which is why the examples start with a date: it keeps the folders sorted on disk too.

02

First-time setup

Open the admin panel. The main screen is a set of panels; each has its own Save. The three buttons across the top open the public site, the site as seen from inside the container, and the Library Explorer.

  1. Master Config. Set siteName (browser tab and topbar), siteAddress (your public URL, used in link previews when someone shares a post), slogan (centered in the topbar) and bottomText. Leave the hosting block alone: Railway supplies the port, and the admin port is reached only through the password proxy.
  2. Logo. Use the logo uploader panel to set media/logo.png. The favicon set is generated from it the next time the service starts, so after uploading a logo, redeploy once from the Railway dashboard.
  3. Theme. Colours, sizes and fonts for the page, topbar, sidebar, dropdowns and code blocks. Fonts come from Google Fonts; paste a Google Fonts API key into apiKeys.googleFonts in Master Config to enable the font picker.
  4. Contact Info. The links behind the avatar at the top right of the public site. Text, link and image per entry. The shipped entry points at your son's site; keep it or replace it.
  5. Backups. In Master Config, set backup.path to /data/backups, pick an interval and time, and tick enabled. Anywhere outside /data is wiped on every deploy.

Custom domain. In Railway, open the canaancope-land service, Settings, Networking, and add your domain. Then update siteAddress here so shared links and previews use it.

03

Libraries

Open the Library Explorer from the admin panel. The left rail lists every library plus All Blogs (a virtual view of everything) and About Me. Right-click a library or entry to rename, move or delete it. Drag libraries to reorder them in the topbar dropdown.

Creating a library

Click New Library and give it a name and a path. The path is the URL segment and the folder name, so notes becomes /notes. Two options matter:

  • Use dates. Posts sort by their last date, newest first, and the library page gets a By Month menu. Undated posts fall to the bottom. Drag-sorting is off in dated libraries because the dates decide the order.
  • Private. The library is left out of public menus but still loads at its URL if someone has the link.

Always create libraries here, not over SSH. New Library also writes the library's index.html page. A folder made by hand shows up in the explorer but its public URL returns the 404 page.

Inside a library, New Folder makes a grouping folder. Folders can nest as deep as you like, and a folder's folder.json holds a display name and its position.

04

Posts

Pick a library or folder in the explorer and click New Blog. Give it a folder name. This is the URL slug, so use letters, digits, hyphens and underscores. The explorer creates config.json, an empty content.md and a media folder, then opens the editor.

config.json

Edit it in the config.json tab of the editor, or inline from the explorer list. Save before switching tabs.

FieldWhat it does
nameThe title shown on the page. Blank falls back to the folder name.
dateA list of "YYYY-MM-DD" strings. One entry is a single date, two entries show as a range. The last entry decides sort order in dated libraries. Leave empty for undated.
descriptionOne line used in link previews when the post is shared. Not shown on the page.
featuredtrue puts the post on the home page.
goAfterOrdering in undated libraries. The folder name of the sibling to follow, or first_blog to pin to the top. Dragging in the explorer sets this for you.
privatetrue hides the post from listings and the home page. It still loads at its URL.

Post URLs are /library/slug, for example /notes/2026-09-12_welcome. That link carries a preview card when pasted into a chat, then opens the library page scrolled to the post.

05

Writing content.md

The editor is plain text with a live Show Preview. The body is Markdown, but the engine only renders text that sits inside a row block. Anything outside a block is ignored, so an empty-looking post usually means the tags are missing.

Row blocks

Rows are numbered and render top to bottom by number. A row is either full width or split into two halves.

[P1]
Full-width row. Normal Markdown inside: headings, lists, links, code.
[/P1]

[P2a]
Left half of row 2.
[/P2a]
[P2b]
Right half of row 2. Both halves must exist.
[/P2b]

[M3]
Shown only on phones and narrow windows (768px and under). Removed on desktop.
[/M3]
  • The closing tag must match the opening tag exactly: [P2a] closes with [/P2a].
  • Numbers only order the rows. Gaps are fine; [P1] then [P5] works.
  • On phones, a split row stacks left then right. An [M…] block can also sit inside a [P…] block; it is stripped on desktop and rendered as its own row on mobile.

Media and embed tags

Inside a row, anything wrapped in angle brackets that names a file in the post's media folder becomes a player, an image or a card. Tags the engine does not recognise are left as text.

TagResult
<photo.jpg>Image, click to zoom. Accepts png, jpg, jpeg, webp, svg, avif.
<anim.gif>Animated image; always loops, muted.
<clip.mp4>Video with normal controls. mp4 or webm.
<clip.mp4 loop>Video that autoplays muted and loops, like a GIF.
<track.mp3>Audio player. mp3 or wav.
<./trip>A subfolder of media shown as a gallery: thumbnail on the page, full gallery on click. Folder names may use letters, digits, underscore and hyphen only, no spaces.
<link:https://…>A 16:9 preview card that opens the link in a new tab.
<link:https://…|click>The same card, but live: the page is embedded and scrollable, with an open-in-new-tab button.
<stl:part.stl|#202020|#e3c356>Drag-to-orbit 3D viewer. All three parts are required: file, background colour, model colour.

How tags sit in text

  • A tag in the middle of a sentence renders inline, and the sentence flows around it.
  • Two or more tags, each alone on its own line and nothing else in that block or half, render as a vertical stack in one cell.
  • A block or half that contains only one tag becomes a media-only cell, which is the usual way to put a photo beside a paragraph: text in [P2a], <photo.jpg> in [P2b].
# A worked example
[P1]
## Camping at the lake
Three days, one canoe, no signal.
[/P1]

[P2a]
The lake was glass every morning. Loons at dusk, both nights.
[/P2a]
[P2b]
<morning.jpg>
[/P2b]

[P3]
<./day-two>
<paddle.mp4 loop>
[/P3]
06

Media

The panel on the right of the editor is the post's media folder. Upload picks files, or drop or paste them anywhere in that panel. Drag to move files between folders; right-click to rename. New Folder creates a gallery folder for the <./name> tag.

  • A gallery shows its images in alphanumeric order and uses the first as its thumbnail. Number your files (01-arrival.jpg, 02-camp.jpg) to control the order.
  • An image named thumb with any extension becomes the thumbnail for link cards in that post.
  • Upload originals. The engine makes compressed AVIF and MP4 variants in the background with ffmpeg and serves those to visitors, keeping the original for zoom and download. Big videos take a minute or two to appear compressed; the page works in the meantime.

The About Me page has the same media panel, and its files live under public/aboutme/media.

07

Home page and About Me

The home page shows every post marked featured, from any library, followed by the About Me content. The topbar carries the Libraries dropdown, the slogan, and the avatar that opens the Contact Info sidebar. The credit at the bottom left shows the engine version and links to the source.

About Me is edited from the explorer rail. It has a content.md and media only, no config, and it uses the same row and tag syntax as a post.

The 404 page lives at public/404 and ships with your son's clone-trooper video. Replace the files there if you want your own.

08

Keeping it running

What is saved where

The Railway volume at /data holds config, public and extensions. Everything you do in the admin panel lands there. The engine's own files (its CSS, scripts and page templates) are refreshed from the pinned release on each deploy, but any of those files you have changed are left alone and noted in the deploy log.

Updating the engine

The update-checker panel in the admin compares the running version with the latest GitHub release. The in-app updater cannot run in a container, so to update:

  1. Open the wrapper repo at github.com/NormCopeland/canaancope-land-railway.
  2. Change ARG UPSTREAM_TAG=26.9.2 at the top of the Dockerfile to the new tag.
  3. Commit and push. Railway rebuilds both services and the site comes back on the new version with your content intact.

Shell access

From the repo folder on your Mac, the Railway CLI opens a shell inside the running container:

cd ~/Documents/github/canaancope-land-railway
railway ssh                      # the site container
railway ssh --service admin-proxy # the password proxy
railway logs                     # live deploy logs

Inside, posts are under /data/public/libraries. Files you add by hand are picked up without a restart, but create libraries in the admin panel as noted above.

Backups and the archive

With backup.path set to /data/backups, the engine copies the site on the schedule you chose and lists each copy in the Archive panel. Railway can also snapshot the whole volume from the service's Volume tab, which is the safer of the two.

Changing the admin password

The proxy stores only a bcrypt hash. Make a new one on your Mac, paste it into the ADMIN_PASSWORD_HASH variable on the admin-proxy service in Railway, and redeploy that service.

htpasswd -nbB -C 12 norm 'new-password' | cut -d: -f2

Quick fixes

SymptomLikely cause and fix
Post shows title onlyThe body is not inside [P1]…[/P1] tags. Wrap it and save.
Library URL gives 404The library folder was made by hand. Delete it and use New Library, or copy the page template in over SSH.
Tag prints as textFilename or extension does not match a file in media, a gallery name has a space, or an STL tag is missing one of its three parts.
Post in wrong orderDated library: check the last date in date. Undated: drag it in the explorer, which rewrites goAfter.
Favicon is the defaultUpload a logo, then redeploy the site service once so the favicon set is generated.
Admin says update availableBump the tag in the wrapper repo Dockerfile and push.
Changes vanished after deploySomething was written outside /data. Backups belong in /data/backups; everything else the panel writes is already on the volume.
